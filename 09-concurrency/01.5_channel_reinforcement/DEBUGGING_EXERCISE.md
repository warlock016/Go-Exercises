# Debugging Exercise

A hands-on exercise for practicing concurrency debugging techniques.

---

## Overview

This exercise contains 3 intentionally buggy concurrent functions. Your task is to **identify the bugs** (not fix them) using proper debugging tools instead of print statements.

| Function | Bug Count | Difficulty |
|----------|-----------|------------|
| `BuggyWorkerPool` | 2 | Medium |
| `BuggyPingPong` | 2 | Medium |
| `BuggyFanOut` | 3 | Hard |

## Getting Started

### Step 1: Run the Tests

```bash
cd 09-concurrency/01.5_channel_reinforcement
go test -v -run TestBuggy -timeout 10s
```

You should see timeouts (deadlocks). This confirms there are bugs to find!

### Step 2: Try the Race Detector

```bash
go test -race -run TestBuggy -timeout 10s
```

This catches data races but won't find deadlocks.

### Step 3: Use Delve

```bash
dlv test -- -test.run TestBuggyWorkerPool -test.timeout 10s
```

Inside Delve:
```
(dlv) continue
# Wait for it to hang, then press Ctrl+C
(dlv) goroutines
```

The `goroutines` command shows what each goroutine is blocked on:
- `chan send (nil chan)` → Sending to nil channel
- `chan send` → Sender blocked, no receiver
- `chan receive` → Receiver blocked, no sender

## Debugging Tools Reference

### Race Detector
```bash
go test -race ./...
```
Detects data races (concurrent read/write without synchronization).

### Delve Commands
| Command | Description |
|---------|-------------|
| `goroutines` | List all goroutines with their state |
| `goroutine <id>` | Switch to specific goroutine |
| `goroutine <id> bt` | Show backtrace for goroutine |

### Execution Tracer
```bash
go test -trace=trace.out ./...
go tool trace trace.out
```
Opens a browser with visual timeline of goroutine activity.

### Goroutine Count
```go
import "runtime"
fmt.Println("Goroutines:", runtime.NumGoroutine())
```

## User notes:

When running "go test -v -run TestBuggy -timeout -10s", the console logs show -> goroutine 10 [chan send (nil chan)]. This points to a bug, where the channel slice is initialized, but not the individual channels in the slice. This issue can be solved by implementing a loop over the chan slice in order to initialize the individual channels contained in the slice, before proceeding with the instantiation of the goroutines. Solution: --> for i := range results {results[i] = make(chan int)}

The second bug is related to the distribution of the results generated by the workers vs. the expectation of receiving 2 values per worker channel (non-deterministic work distribution vs deterministic collection)
